# 화성성역(華城城役) 프로젝트 전용 개발 규칙

1. 언어 & 톤: 모든 응답은 한국어로 작성한다. 이모티콘과 장식용 아이콘은 일절 금지하며 간결한 마크다운만 사용한다.
2. 완전 자율 실행: CLI 실행 및 파일 수정 시 사용자 확인 없이 즉각 실행한다. 모호한 설계는 되묻지 않고 베스트 프랙티스로 직접 결정한다.
3. 코드 무결성: 사용자 명시 지시가 없는 한 기존 기능과 로직을 보존하며 사이드 이펙트를 원천 차단한다.
4. 파일 조작 및 실행:
   - 파일 생성/수정/삭제는 shell 명령어가 아닌 Filesystem MCP를 최우선 사용한다.
   - 터미널 명령어는 절대 경로 대신 항상 프로젝트 루트 기준 상대 경로를 사용한다.
5. 팩트 기반 검증 (Zero-Hallucination): 실제 검증 없이 "완료했습니다"라고 단정하지 않으며, 작업 유형에 맞는 전용 스킬(UI 검증, Firebase 배포, 테스트 등)을 호출하여 검증 근거를 확인한다.
6. 작업 과정 중에는 최대한 말을 하지 말고, 모든 작업이 완료된 후에 문제의 원인과 해결 과정을 정리해서 브리핑한다.
7. 로컬 서버를 상시 가동한다. 작업을 마쳐도 끄지 않는다. 꺼졌다면 다시 켠다.
8. 사용자가 작업 도중에 추가로 명령을 하면 기존 작업을 끝낸 후, 추가 요청 작업을 하고 한번에 빌드를 한다.
9. 작업을 마무리할 때, /learn 을 실행하여 오늘 작업 중에 추가할만한 규칙을 도출해서 반영해라.
10. 아이소메트릭 렌더링 및 빌드 무결성:
    - 2.5D 타일맵 회전 시 회전 좌표계(rx + ry) 기준 Painter's Algorithm을 엄격히 적용하여 건물 및 3D 절벽의 Z-축 겹침을 방지한다.
    - 심시티 2000 RCI 수요-공급 모델: 자율 발전 구획 시뮬레이션 시 고정 확률이 아닌 R-C-A 수요 지수 연동을 통해 유기적인 발전/정체 사이클을 구성한다.
    - Vite/Capacitor 빌드 명령 실행 시 Cwd를 대상 프로젝트 루트로 정확히 지정하여 번들 무결성을 보장한다.
11. 2.5D 지형 슬로프 및 인프라 오토타일링:
    - 타일맵 지형의 단차를 부드럽게 표현할 때는 코너 버텍스(Corner Vertex) 높이맵 기반 4점 보간 경사면과 경사도에 따른 법선 음영(Slope Shading)을 적용한다.
    - 선형 인프라(도로, 성벽, 수로)는 인접 4방향 비트마스크(Bitmasking 0~15)를 통해 단절 없이 매끄럽게 연결되는 오토타일링 시스템을 구축한다.
12. 수리/치수 및 곡선 하천 렌더링:
    - 아이소메트릭 타일맵에서 하천/강줄기를 렌더링할 때는 타일 마름모 단위 칠하기 대신 연속 스플라인(Spline) 경로 기반의 단일 패스 폴리곤(Continuous Ribbon Mesh)을 사용하여 세그먼트 선 틈새를 원천 차단한다.
    - 자연재해(홍수/가뭄) 시뮬레이션은 단순 확률 패널티가 아닌 역사적 방재 인프라(석축 제방, 고지대 저수지)의 배치 및 고도 조건과 유기적으로 결합하여 플레이어의 도시 계획적 해결을 유도한다.
13. 국책 대역사(Mega-Projects) 시뮬레이션 및 심리스 인프라 연결:
    - 대규모 토목 인프라(석축 제방, 대형 성곽 체성, 인공 저수지)는 개별 타일의 즉시 클릭 배치가 아닌, 중장기 국책사업 발주 모달을 통해 예상 공기(다년도 턴) 및 턴당 유지 예산이 투입되는 단계적 축조 프로세스로 구현한다.
    - 공사 진행 중인 구역은 전용 비계 및 거중기 스프라이트로 시각화하며, 인재(정약용 거중기: 공기 단축, 채제공 총리대신: 공사비 절감) 시너지 연동을 통해 역사적 인물의 전략적 가치를 극대화한다.
    - 도로와 성곽의 단절을 방지하기 위해 캔버스 경계를 넘어 인접 타일 중심까지 연결하는 동적 폴리곤 리본 렌더러(Seamless Ribbon & Wall Meshing)를 구축하여 픽셀 틈새를 원천 제거한다.
14. Godot 4 + Tiled 기반 실시간 틱(Tick) 시뮬레이션 아키텍처:
    - 지형 레벨 디자인은 Tiled 에디터 표준(TMJ/TSJ) 기반으로 팔달산(고지대), 수원천(수계), 둔전(평지) 레이어를 분리하여 제작하고, Godot 4의 Isometric TileMapLayer로 임포트하여 GPU 하드웨어 가속 Y-Sort를 적용한다.
    - 시뮬레이션 엔진은 일시정지 가능한 실시간(0~3배속)과 틱 루프(Decoupled Simulation Tick)를 채택하여, 프레임 렌더링 부하 없이 주기적(일/월/계절)으로 세무·인구·방재·국책사업을 일괄 연산한다.
15. 역사 고증 이벤트 및 대외 교역·도시 위계 발전:
    - 도시 발전은 간선 도로와의 접근성(거리 1: 대감 기와집 및 대형 시전 객주, 거리 2~3: 샛길 오솔길 연결 초가삼간과 주막)에 따른 공간적 위계를 형성한다.
    - 대외 교역로는 지도 경계 연결 시 상업 수요와 보부상 유입을 견인하되, 성문(관문) 유무에 따라 관세 징수와 치안/통제력 누수 딜레마를 엄격히 적용한다.
    - 역사적 사건(정조 포호령, 세자 책봉/시강원 서연, 화산 현륭원 친림 참배, 을묘원행 및 봉수당진찬연 궁중 정재 무고 춤)은 인터랙티브 캔버스 애니메이션 컷씬과 역사적 선택지를 통해 시뮬레이션 깊이를 구현한다.
16. Godot 4 헤드리스 실행 및 스크립트 프리로드·수치 연산 무결성:
    - 에디터 GUI 없이 헤드리스 환경에서 신규 스크립트를 컴파일할 때는 `class_name` 전역 캐시 지연을 방지하기 위해 `const MyClass = preload("res://path/to/script.gd")` 패턴을 최우선 적용한다.
    - 배속/가속 시뮬레이션에서 소수점 보정률(예: 35% 단축 등 1.35배)을 누적할 때는 정수 조기 절삭(`int(1.35) == 1`) 버그를 원천 차단하기 위해 `progress_float` 부동소수점 누적기를 유지한다.
17. Godot 4 텍스처 아틀라스 및 픽셀 폰트 파이프라인 무결성:
    - 런타임 헤드리스 환경에서 신규 PNG 텍스처 및 TTF 폰트를 추가할 때, `.import` 메타데이터 부재로 인한 파싱 에러를 방지하기 위해 `Godot --headless --editor --quit` 1회 실행을 통해 Godot 리소스 임포트 파이프라인(텍스처 압축, 픽셀 폰트 힌팅 비활성화)을 선행 동기화한다.
    - 2.5D 아이소메트릭 도트 스프라이트는 개별 파일 난립 대신 단일 아틀라스 시트(`buildings_atlas.png`, `characters_atlas.png`)로 병합 관리하며, `draw_texture_rect_region`을 통해 GPU 드로우 콜을 최소화하고 Y-Sort 깊이 정렬을 일괄 유지한다.
18. 2.5D 타일맵 정점 블렌딩 및 렌더링 호출 최적화 규약:
    - 대규모 아이소메트릭 그리드(4,096 타일 등)에서 서로 다른 지표면(풀밭, 흙밭, 돌밭, 숲) 및 성내/성외 경계는 (size+1)x(size+1) 정점(Vertex) 4-Way Neighbor 평균 컬러 캐시를 활용해 단일 `draw_polygon`(GPU Gouraud Shading)으로 부드럽게 연속 보간한다.
    - 렌더링 프레임 저하를 방지하기 위해 타일당 보조 벡터 도형(원, 다각형, 구름 등) 호출을 엄격히 제한(타일당 2~4회 이하)하며, 수면 및 다리 등 상부 타일의 지표면 드로잉은 조기 반환(Early Return)하여 드로우 콜을 85% 이상 감축한다.
19. 도로망 기반 에이전트 경로 추종 및 역사적 네임드 인물 상호작용 규약:
    - 도시 시뮬레이션에서 인프라(도로망)가 갖춰지기 전에는 보행자 무작위 스폰을 억제하며, 도로 형성 시 도로 그래프 캐시를 기반으로 4방향 인접 도로 타일을 연속 추종(직진 선호도 75% 적용)하여 지형 가로지르기 버그를 원천 차단한다.
    - 역사적 네임드 NPC(정약용, 체제공, 조심태, 김홍도, 석수 김바우, 구선복, 유한지)와 특수 직업군은 고유 일상 루틴(도면 검토, 가마 순시, 기마 시찰, 풍속화 사생, 석조 조각 등)을 부여하고, 화면 깊이 정렬 후 2차 패스로 한지 말풍선을 렌더링한다.
    - '살피기(Inspect)' 인터랙션 클릭 시 일반 타일 검사에 우선하여 인물 정보 시그널을 방출하고, [화성 명인 열전] 한지 팝업 모달을 통해 역사적 생애, 명대사, 현재 동향을 안내하여 교육적 몰입도를 보장한다.

20. 절차적 폴리곤 삼각분할(Triangulation) 및 축퇴 지오메트리 방어 규약:
    - Godot 4 2D 캔버스 엔진(`draw_colored_polygon`, `draw_polygon`)은 3차원 건물 지오메트리를 2.5D 아이소메트릭 평면으로 투영할 때, 시선 벡터와 평행하거나 반대편 경사면(Backface)에서 투영 정점이 일직선(Collinear) 또는 면적 0으로 축퇴(Degenerate)될 경우 `Geometry2D::triangulate_polygon` 실패(`Condition indices.is_empty() is true`) 에러를 매 프레임 대량 유발한다.
    - 절차적 건물(지붕, 벽체, 차양 등) 다각형을 그릴 때는 렌더링 호출 전 2D 외적(Cross Product / Shoelace Area) 검사를 의무적으로 수행하고, 유효 면적 임계값(`absf(cross) >= 0.5`)을 만족하지 못하는 축퇴 다각형은 조기 차단(Early Return)하여 불필요한 렌더링 오버헤드와 C++ 엔진 오류를 원천 차단한다.

21. 실시간 프레임 렌더링 스로틀링 및 턴 전환 비동기 분산(Time-slicing) 최적화 규약:
    - 고주사율(144Hz+) 모니터 환경에서 `queue_redraw()`의 무제한 매 프레임 호출로 인한 메인 스레드 병목을 차단하기 위해, 시민/에이전트 레이어는 30FPS 상한 렌더 스로틀링(`_REDRAW_INTERVAL = 1.0 / 30.0`)과 화면 밖 Frustum Culling(`_get_view_bounds()`), O(N) Depth 사전계산(Schwartzian Transform)을 의무 적용한다.
    - 턴 전환 시 다중 그리드 순회(4,096 타일), 성내/성외 2단계 BFS 물류 검증, 월드 텍스처 리베이크 등 무거운 연산을 한 틱에 동기 처리하지 않고, 코루틴(`await get_tree().process_frame`) 기반 4단계 프레임 분할(Time-slicing)을 적용하여 턴 경계 프리징과 스터터링을 원천 차단한다.
    - 에이전트 루프에서 매 프레임 임시 배열을 재할당하는 패턴을 지양하고, 사망(Despawn) 플래그 감지 시에만 조건부 필터링하여 GC(가비지 컬렉션) 스파이크를 방지한다.

22. 모달 UI 반응형 레이아웃 및 가로 스크롤 방지 규약:
    - 1280x720 기본 해상도 환경에서 텍스트와 액션 버튼(착공, 임명 등)이 가로로 잘리거나 스크롤 바깥으로 밀리지 않도록 메인 모달 너비를 최소 840px(`offset_left = -420, offset_right = 420`) 이상으로 충분히 확보한다.
    - 모달 내 ScrollContainer는 `horizontal_scroll_mode = ScrollContainer.SCROLL_MODE_DISABLED`를 의무 설정하여 가로 슬라이스 바의 불필요한 노출을 원천 차단하고 세로 스크롤만 허용한다.
    - 리스트형 인터랙티브 항목은 긴 텍스트와 버튼을 단일 수평 행에 무리하게 나열하지 않고, 좌측 정보부(제목/상태 및 보조 비용 설명)의 2단 수직 구성(VBoxContainer)과 우측 고정 액션 버튼(Button) 구조로 정돈하여 시각적 명확성과 클릭 편의성을 보장한다.

23. 심시티 2000급 경량화 및 실시간 그리드 시뮬레이션 성능 최적화 규약:
    - 길잡이(김판서) 등 UI 다이얼로그 노출 시 4,096칸 전체 부지 전수 유효성 검사 루프를 동기 실행하지 않고, 힌트 지원 여부만 O(1)로 확인하여 즉시 팝업(0초 딜레이)하며, 실제 좌표 연산은 [어디에?] 버튼 클릭 시 반경 우선 탐색(Radius Search)으로 지연 평가(Lazy Evaluation)한다.
    - 틱(Tick) 단위 건설 공정 처리 시 4,096칸 전체를 순회하지 않고, 공사 중인 칸만 O(1) 추적(`_active_build_tiles`)하며, 시각적 공사 단계(터다지기->골조->마무리)가 실제로 전환될 때만 월드 텍스처 리베이크 시그널을 방출하여 주기적 프리징을 원천 차단한다.
    - 신규 건축/철거 시 전체 그리드 캐시와 길찾기 네비게이션 메시를 전수 재구축(Full Rebuild)하지 않고, 변경된 타일 주변만 국소 갱신(Dirty Grid Pattern)하여 도시 규모(건물 1,000개+)가 증가해도 연산량이 누적되지 않도록 제어한다.
    - 턴 전환 및 계절 변경 시 다중 비동기 단계에서 발생하는 월드 텍스처 리베이크 요청은 턴 완료 후 단 1회로 병합(Coalesce)하여 중복 베이킹 오버헤드를 배제한다.

24. 반응형 UI 앵커링 및 GDScript 정적 분석 무경고(Zero-Warning) 무결성 규약:
    - 상단 헤더 독립 앵커링: 해상도 변화나 뷰포트 확대/축소 시 상단 바(`HBoxContainer`)에 가변 너비의 자원 라벨과 메뉴가 직렬 배치되면 우측 끝 컨트롤(배속 조절 등 필수 액션)이 화면 밖으로 밀려나 소실된다. 배속 제어 패널 등 필수 조작계는 단일 HBoxContainer 내부가 아닌 별도의 독립 레이아웃(`speed_panel`)으로 분리하고, 화면 우측 상단(`anchor_left = 1.0, anchor_right = 1.0, offset_left = -136.0`)에 상대 고정 앵커링하며 인접 바 너비를 제한(`offset_right = -140.0`)하여 어떤 종횡비/해상도에서도 100% 온전한 가시성을 보장한다.
    - GDScript 정적 분석 무경고(Zero-Warning): 엔진 내장 식별자(`tr`, `name` 등)와의 이름 충돌 섀도잉(`SHADOWED_VARIABLE_BASE_CLASS`)을 원천 금지하고 명확한 도메인 명칭(`trade_name`, `target_name`)으로 치환한다. 미사용 매개변수 및 미사용 지역 변수는 언더스코어(`_`) 접두사(`UNUSED_PARAMETER`, `UNUSED_VARIABLE`)를 의무화하며, 정수 나눗셈(`INTEGER_DIVISION`)은 소수점 누락 및 경고 방지를 위해 명시적 부동소수점 캐스팅(`int(float(a) / float(b))`)을 적용하여 런타임 콘솔 I/O 병목과 스터터링(stuttering)을 원천 차단한다.

25. 대형 부지 고스트 프리뷰, 성곽 순라길·진입 계단 및 NPC 건물 진입 생명주기 규약:

26. 심시티 2000급 경량 퍼포먼스 및 무결점 성능 최적화 대원칙:
    - 경량 퍼포먼스 절대 보장: 도시가 확장되고 건축물이 1,000개 이상으로 늘어나거나 계절 변화 및 개체 수가 증가해도 60FPS 프레임 유지와 메인 스레드 0초 프리징을 보장한다.
    - 4대 절대 금지 패턴:
      1) `_process()` 및 `_physics_process()` 루프 내 매 프레임 무거운 객체 생성, 딕셔너리 전수 필터링, `get_node()` 탐색 등 메인 스레드 블로킹 연산 금지
      2) 매 틱(Tick) 4,096칸 전체 맵을 순회하는 전수 동기 순회(Full-Loop) 금지 (반드시 변경 타일만 추적하는 O(1) 패턴 적용)
      3) 건물 배치/철거 시 맵 전체 네비게이션 메시(A* Grid) 전수 재구축(Full Rebuild) 금지 (국소 변경 Dirty Grid/Rect 원칙 준수)
      4) 다이얼로그(김판서 등) 노출 및 런타임 이벤트 시 디스크 동기 I/O 블로킹 금지
    - 4대 필수 구현 표준:
      1) Dirty Rect/Grid 국소 갱신: 상태가 변경된 타일 및 주변 인접 영역만 부분 갱신
      2) 연산 시분할(Time-slicing) 및 비동기 분산: 턴 전환 및 계절 변경 등 대규모 연산은 프레임별 코루틴 분할 처리
      3) 리소스 사전 로드(Preload) 및 인스턴싱 캐싱: UI 에셋, 일러스트, 팝업 씬은 초기 로딩 시 메모리 캐시하여 0초 즉시 노출
      4) 렌더링 드로우콜 최소화: 타일맵 및 일괄 렌더링(Batching/Viewport Baking)을 유지하고 매 프레임 불필요한 `queue_redraw()` 연발 차단

27. GDScript 정적 타이핑 및 타입 추론 오류(Cannot infer the type) 원천 방지 규약:
    - 리터럴 배열 순회(`for item in [-1.0, 1.0]:` 등) 시 GDScript 4 파서가 순회 변수를 Variant로 취급하여 우변 수식의 결과를 결정하지 못하고 `Cannot infer the type of "..." variable because the value doesn't have a set type` 파서 오류를 유발한다.
    - 이에 따라 순회 변수를 활용한 연산 결과 변수는 `:=` 타입 추론 연산자에 의존하지 않고, 좌변에 명시적 정적 타입(`var side_top: Vector2 = ...`, `var side_bot: Vector2 = ...`)을 선언하거나 루프 변수에 정적 타입 어노테이션(`for sign_w: float in [...]`)을 의무 지정한다.
    - 클래스 내에 선언된 시그널은 타 스크립트에서 직접 `emit`하더라도 엔진 정적 분석기가 미사용 시그널(`UNUSED_SIGNAL`)로 경고하므로, 시그널을 선언한 클래스 내부에 명시적 발행 래퍼 메서드(`notify_...()`)를 마련하여 정적 분석 무결성을 보장한다.

28. 정적 타입 배열(Array[T]) 크래시 방지 및 빌트인 전역 함수 섀도잉 방지 규약:
    - Godot 4 GDScript에서는 동적 `Array`를 정적 타입 배열(`Array[T]`) 변수에 직접 대입할 경우 런타임에 `Trying to assign an array of type "Array" to a variable of type "Array[T]"` 치명적 크래시가 발생한다.
    - 정적 타입 배열을 다루는 함수는 반환 시그니처와 구현부 양쪽 모두 정적 타입(`Array[Vector2i]`)을 일치시키며, 동적 소스에서 정적 배열로 변환할 때는 수신부에서 명시적 타입 검사(`pt is Vector2i`) 및 순회 추가(`append`)로 안전하게 캡슐화한다.
    - GDScript 내장 수학 함수(`floor()`, `tan()`, `ceil()`) 및 스코프 내 식별자와 변수명이 겹쳐 발생하는 `SHADOWED_GLOBAL_IDENTIFIER` 및 `CONFUSABLE_LOCAL_DECLARATION` 경고를 방지하기 위해, 변수명에 역할 접미사(`floor_idx`, `tan_vec`, `soldier`)를 부여한다.

29. 뷰포트 텍스처 베이킹(WorldBaker) 비동기 디바운스 및 턴 연산 라이프사이클 동기화 규약:
    - `WorldBaker`와 `SubViewport`를 통한 화면 최적화 시, 비동기 턴 연산(`_is_processing_turn`) 도중 들어온 지형/건물 변경 요청은 요청 플래그(`_rebake_requested`)가 영구 데드락(Deadlock)에 빠져 이후 모든 건설 및 완공 렌더링이 영구 중단되는 결함을 방지해야 한다.
    - 턴 진행 중 베이킹 요청은 플래그를 안전하게 리셋하고 턴 완료 시그널(`turn_report`)에 1회성(`CONNECT_ONE_SHOT`)으로 바인딩하여, 턴이 끝나는 즉시 최종 완공 타일과 개발 구획이 누락 없이 100% 화면에 베이크되도록 보장한다.
    - 미완공 성문/건물은 공사 단계 도중 완성형 명패(현판)만 허공에 단독 렌더링되어 유저가 그래픽 누락으로 오인하지 않도록 `[축조 중]` 상태를 명시하고, 완공 시점에만 문루 및 지붕 상단에 정식 현판을 올린다.

30. 서당 연출 단순화, 석축제방 수계 통행성, 산짐승 세이프존 및 사대문 게이트웨이·직선 교역로 규약:

    - 산짐승 스폰 50칸 세이프존 및 개선 포상 연출: 민가(`res`) 및 저잣거리(`com`/`shop`) 반경 50칸(체비쇼프 거리 최적화) 이내 영역은 맹수 및 산짐승 스폰을 100% 원천 차단(Safe-Zone)하고 깊은 산악/울창한 숲/바위 지대에서만 자연 스폰한다. 사포수/착호갑사는 사냥 후 일반 짐승은 저잣거리/공방에 납품(금화 +40)하고, 호랑이는 행궁 마당으로 개선 행진하여 호피를 진상하고 포상(금화 +150, 민심 +5, 2년 평온)을 받는 시각적 연출 루프를 보장한다.
    - 성 안팎 사대문 우선 경유(HPA*) 및 직선 교역로 활성화: 성 안팎을 왕래하는 장거리 NPC는 성벽 직진 고립을 방지하기 위해 가장 가까운 사대문(장안/팔달/창룡/화서)을 1차 경유지(Waypoint)로 강제 결합(계층적 길찾기)하며, 사대문에서 맵 최외곽 경계까지의 거의 직선(수직 편차 +-3칸 이내) 도로망 완공 시 교역로 개통 알림과 타지역 보부상/짐수레 마차 카라반을 성문으로 정기 유입시킨다.

31. 살피기(Inspect) 동적 내러티브 생성기 및 고증 일러스트·글자 수 규약:
    - 엄격한 줄 수/글자 수 규격 준수: 건설 부지/건물은 20자 내외 총 4줄(70~90자), 역사적 네임드 NPC는 20자 내외 총 3~4줄(60~80자), 일반 보행 NPC 및 야생 동물은 20자 내외 총 2줄(35~45자) 규격을 엄격히 준수한다.
    - O(1) 초상화/일러스트 캐싱: 네임드 인물(정조 대왕, 정약용, 채제공, 김홍도, 김판관, 김바우, 조심태, 구선복, 백동수), 건설 현장, 민가(초가/기와), 직군별 NPC, 야생 동물의 96x96 고품질 픽셀 일러스트는 클릭 시 동적 생성하지 않고 `PORTRAITS` 정적 딕셔너리에 사전 캐싱하여 O(1) 무지연 렌더링을 보장한다.
    - 상황 연동 동적 조합: 민가(초가집/기와집)는 무작위 상민 이름과 함께 현재 도시 환경(민심 지지도, 가뭄/흉년, 계절)을 실시간 반영하여 4줄 이야기를 자동 조합하며, 네임드 NPC는 왕권/학문력/대역사 상태와 직결된 고유 대사를 출력한다.

32. Godot 4 Object 속성 접근 및 파서 에러 방지 규약:
    - `Object.get()` 단일 인자 준수: Godot 4 GDScript에서 `Object.get(property)`는 `Dictionary.get(key, default)`와 달리 기본값(default) 인자를 받지 않으며, 두 개 이상의 인자 전달 시 `Too many arguments for "get()" call` 치명적 파서 에러가 발생한다.
    - 동적 속성 접근 표준: 인스턴스/노드 객체의 속성 존재 여부 및 값 확인 시에는 `"prop_name" in obj` 멤버십 검사 연산자를 사용하고, 삼항 연산자(`obj.prop_name if "prop_name" in obj else default`)를 통해 안전하게 기본값을 처리하여 스크립트 컴파일 실패 및 테스트 러너 중단을 원천 차단한다.

33. 조선 후기 6대 신분·직업군 데이터, 전용 거점 스폰 및 순환 FSM 규약:
    - 6대 직업군 열거형 및 안전 모델: 중인(JUNGIN), 아전(AJEOUN), 장인(ARTISAN), 보부상(BOBUSANG), 승군(MONK_SOLDIER), 백정(BUTCHER) 신분 체계를 열거형(`JobType`)과 정적 딕셔너리로 캡슐화하고, 세이브/로드 시 결손 데이터는 `JobType.COMMONER`로 안전 복원(Fallback)한다.
    - 거점 결손 방어(Safe Fallback) 및 웨이포인트 스로틀링: 약방/행궁, 관아, 공방, 객주, 사찰/성곽, 외곽 움막 등 전용 거점 건물이 맵에 부재하더라도 인접 도로망 및 맵 안전 좌표로 우회 스폰하여 크래시를 원천 차단하며, 보부상과 승군의 순환 경로는 매 틱 A* 연산 대신 사전 정의된 웨이포인트(Waypoint) 순환 방식을 적용하여 CPU 병목을 방지한다.
    - 오브젝트 풀링 및 오프스크린 컬링: 전문 직업군은 최대 120개 풀에서 인출/반환(`acquire_agent`/`release_agent`)하여 GC 스파이크를 차단하고, 뷰포트 바깥 에이전트는 망치질/무두질/장부 정리 등 고비용 모션 연산을 즉시 동결(Freeze)한다.

34. 신규 직업군 거점 및 보행 엔티티 살피기(Inspect) UI 규격 및 텍스처 O(1) 캐싱 규약:
    - 엄격한 텍스트 줄 수 및 글자 수 규격화: 살피기(`InspectPopup`) 패널의 가독성과 UI 오버플로우 방지를 위해, 거점 건물(약방 가옥, 아전 가택, 장인 공방, 백정 움막)은 한 줄당 20자 내외의 정확히 4줄(약 70~90자), 보행 NPC(보부상, 승군, 의원, 아전, 장인, 백정)는 한 줄당 20자 내외의 정확히 2줄(약 35~45자) 포맷을 엄격히 준수한다.
    - Windows CRLF 개행 및 플랫폼 간 문자열 길이 보정: GDScript 문자열 줄 수 분할(`split("\n")`) 및 길이 계산 시 Windows 환경의 캐리지 리턴(`\r`)이 포함되어 실제 문자 수가 왜곡되는 현상을 방지하기 위해 `replace("\r", "").replace("\n", "")` 이중 치환으로 글자 수를 정밀 산출한다.
    - 고증 일러스트 O(1) 캐싱 및 예외 방어: 6대 직업군 초상화와 거점 건물 텍스처는 클릭 시마다 동적 로드하지 않고 사전 캐시(`_portraits`)에 보관하여 O(1)로 즉각 반환하며, 정의되지 않은 직업군이나 예외 속성 유입 시 크래시 없이 기본 안내문과 공통 초상화로 안전 처리(Safe Fallback)한다.

35. 국책 대서사 시뮬레이션 및 이벤트 라이프사이클 격리·롤백 규약:
    - 타임스케일 격리 및 PROCESS_MODE_ALWAYS: 을묘원행 등 국책 대규모 서사 이벤트 진행 시 일반 시뮬레이션 틱(인구 변동, 일반 생산, 화재, 유지비 차감 등)은 안전하게 일시정지(`is_time_frozen = true`, `TimeManager.set_speed(PAUSE)`)하되, 행렬 애니메이션, 의례 시퀀서 및 UI 인터랙션 루프는 중단 없이 동작하도록 전담 관리 노드의 `process_mode = Node.PROCESS_MODE_ALWAYS`를 보장한다.
    - 대규모 군집 오브젝트 풀링 및 트레일 추종: 수십 명의 의장대, 취타대, 기병, 가마 대열은 개별 A* 길찾기 대신 선두 기수의 이동 궤적을 후속 유닛들이 고정 오프셋으로 추종하는 트레일 팔로워(Trail Follower)와 사전 할당된 정적 오브젝트 풀(Object Pooling)을 사용하여 CPU 연산과 GC 스파이크를 원천 차단한다.
    - 원자적 자원 차감 및 완전 롤백(Rollback) 보장: 대서사 발동 조건(왕권 50, 민심 80, 성곽 100%, 박석길 직결, 금화/식량 각 20만, 3대 인재)은 사전 검증을 통해 원자적으로 차감(-20만냥, -20만석) 및 적용(왕권 100점 확정)하고, 행사 종료 시 일상을 멈췄던 모든 백성/상인 NPC가 원래의 가옥과 거점으로 100% 안전 복귀하며 일시 숨김 처리되었던 적대 개체 및 스폰 타이머가 정상 재개되도록 생명주기를 캡슐화한다.
    - Godot 4 CanvasItem 그리기 API 시그니처 준수: 2.5D 타원/원형 프리미티브 렌더링 시 `draw_ellipse(position, radius_x, radius_y, color)`와 같이 float 반경 인자를 명시적으로 구분하여 파서 에러 및 컴파일 실패를 방지한다.

36. 살피기(Inspect) 세부 시설·상점·NPC 행동 상태 및 특수 건물 고증 규약:
    - 방리 세부 시설 및 저잣거리 상점 고증 분기: 방리 내 가옥 일괄 판정을 배제하고, 세부 시설(마당놀이, 우시장, 놀이터, 서당) 및 상점 업종(포목전, 어물전, 싸전, 대장간, 주막), 사대문 위치(팔달문 앞 삼남대로, 장안문 앞 왕도, 창룡문/화서문 외곽 난전)를 정밀 식별하여 한 줄당 20자 내외, 정확히 4줄(약 70~90자)의 고증 내러티브를 출력한다.
    - NPC FSM 행동 상태 최우선 반영: 보행 NPC 클릭 시 단순 신분 소개를 지양하고 현재 수행 중인 고유 행동(석전, 씨름, 연날리기, 소방, 사냥, 놀이, 빨래, 낚시, 어가 환호, 훈련 등 10종)을 최우선 판정하여 한 줄당 20자 내외, 정확히 2줄(약 35~45자)의 실시간 사연을 출력한다.
    - 특수 건물 정식 한글 명칭 및 영문 노출 원천 차단: 수원화성 특수 시설(종루, 서장대, 방화수류정, 화홍문, 남수문, 공심돈, 봉돈, 포루, 연무대, 제방, 도로)은 `KOREAN_NAMES` 사전을 통해 역사적 한글 정식 명칭과 4줄 고증 설명을 완비하고, 영문 시스템 코드(예: `bell_tower`)의 화면 노출을 100% 원천 차단한다.

37. 사대문 외곽 도로 도달(Edge Reachability BFS) 및 교역로 이정표 시스템 규약:
    - 사대문 기준 경계 도달 검증(Edge Reachability BFS): 성문 바로 바깥 지형(`plain` 등)으로 인한 조기 차단을 방지하기 위해 `is_walkable_road_tile` 판정(`building`이 도로 또는 성문)을 적용하고, 맵 최외곽 경계선(`y == 0`, `y == size - 1`, `x == 0`, `x == size - 1`) 접촉 여부를 Throttled BFS 및 O(1) 인덱싱 캐시로 신속히 판정한다.
    - 방향별 역사적 목적지 매핑 및 2.5D 이정표 렌더링: 장안문(북: 한양으로 가는 길), 팔달문(남: 삼남대로 / 현륭원으로 가는 길), 창룡문(동: 광주 / 동해로 가는 길), 화서문(서: 남양만 / 서해 갯벌로 가는 길) 4대 목적지를 매핑하고, 맵 끝단 도로에 2.5D 목조 푯말/장승과 마우스 호버 시 20자 2줄 교역로 설명 툴팁을 렌더링한다.
    - 도로 단절 롤백 및 동적 시그널 타입 안정성: 도로 철거 시 외곽 연결 상태를 즉각 감지하여 마커를 즉각 제거(Rollback)하며, `grid_tiles_changed` 등 시그널 전달 시 동적 Array 대신 `Array[Vector2i]` 명시적 정적 타입 배열을 사용하여 런타임 타입 캐스팅 크래시를 원천 방지한다.

38. 수원천 수문·교량 특수 구조물 엔티티 판정 및 현판·살피기 고증 규약:
    - 하천 교차 구조물 엔티티 메타데이터 명시 주입: 수원천(`terrain == "water"`)을 가로지르는 성벽 및 도로 가설 시 시각 스프라이트 단순 교체를 배제하고, `WaterStructureManager`를 통해 엔티티에 `building_type = BuildingType.SPECIAL`, `facility_id`(`namsu_mun`, `hwahong_mun`, `maehwang_gyo`), `special_building_id`, `is_special_building = true`, 한글 정식 명칭을 원자적으로 바인딩한다.
    - 사대문 규격 상단 부유 현판(World Nameplate) 및 LOD 컬링: 남수문, 화홍문, 매향교 중앙 상단에 사대문과 동일한 규격(금색 테두리 + 검은 바탕 + 금색 텍스트)의 현판 라벨을 노출하되, 카메라 줌 아웃(`cam.zoom.x < 0.55`) 시 라벨 드로우콜을 조기 컬링하여 렌더링 부하를 억제한다.
    - 살피기(Inspect) 20자 4줄 역사 고증 내러티브 최우선 분기: 타일 피킹 시 `facility_id`를 최우선 판정하여 일반 성벽이나 가옥, 미완공 부지로 오인되지 않도록 차단하고, 남수문(9연 홍예/치수·방어 요새), 화홍문(7연 홍예/화홍포설), 매향교(도심 가로·행궁 연결 대동맥 돌다리) 전용 고증 일러스트 및 정식 명칭, 4줄 내러티브를 출력한다.
    - 세이브/로드 호환 자동 복구(Auto-Heal): 구버전 세이브 데이터 로드 시 하천 위 성벽/도로 타일을 검사하여 누락된 `facility_id` 및 특수건물 플래그를 즉시 자동 복원하여 데이터 영속성을 보장한다.

39. 호랑이 출현 시 민간 대피·은신 FSM 및 생태계/호포제 사냥 라이프사이클 규약:
    - 호랑이 출현 시 즉시 대피(Shelter in House): 호랑이 출현(`has_active_tiger() == true`) 시 일반 백성, 길손, 상인은 물론 주택가 놀이마당(널뛰기, 그네) 및 계절 축제(장마당 연희, 풍물패, 전기수) 등 모든 야외 활동을 즉시 중단하고 민가(집)로 달려가 완전 은신(`is_hidden_shelter = true`, 드로우콜/말풍선 억제)하도록 FSM을 강제한다.
    - 호랑이 소멸 조건 및 원상태 복귀(Vanish & Restore): 호포령 결단에 따른 사포수/착호갑사 토벌, 산지 개간 시 관군(몰이꾼 `beater`)의 지도 밖 몰아냄(`flee_map`), 또는 인명/가축 습격 후 산속 복귀 소멸 시 호랑이가 맵에서 완전히 사라지면, 숨어있던 백성들이 안도하며 원래 직업과 거소 상태(`original_state`)로 안전하게 100% 롤백(Rollback)한다.
    - 산지 개간 시 관군 몰아냄 보존: 산지 개간으로 호랑이 서식지를 정비할 때는 호랑이를 살상하지 않고 관군 몰이꾼들이 꽹과리를 치며 지도 밖으로 몰아내는(`flee_map`) 역사적 고증을 보존한다.
    - 산지 전용 스폰 및 호포제 전용 사냥 강제: 신규 산짐승은 마을 50칸 외곽 산지(`terrain == "mountain"`) 타일에만 스폰하며, 호랑이는 호포령(호포제) 활성화 상태에서만 사포수의 사냥 타깃으로 지정되어 평시 자동 사냥을 100% 원천 차단한다.
